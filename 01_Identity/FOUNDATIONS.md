# Organization Foundations

> 本文定义组织级、跨项目且相对稳定的基础身份。它回答四个不同层次的问题：我们相信什么、希望世界变成什么样、为何存在，以及我们认为变化如何发生。

## 1. Philosophy / 世界观

> **Knowledge belongs to the commons; perspective belongs to the individual.**
>
> **知识属于公共知识域；视角属于个人。**

知识应尽可能成为可获取、可理解、可复用、可再创造的公共基础；与此同时，个人应保有形成自身理解、判断与视角的主体性。

这里的重点不是让所有人得到同一种答案，而是让共同的知识基础能够支持不同个体形成自己的 perspective，并进一步产生新的 creation。

## 2. Vision / 愿景

> **A world where knowledge forms a shared commons, individuals retain agency over perspective, and creation continuously expands the commons.**
>
> **一个知识成为共享公共基础、个人保有形成自身视角的主体性、创造持续扩展公共知识的世界。**

愿景描述的是组织希望长期促成的未来状态，而不是某一种产品形态、技术路线或当前项目边界。

因此，组织本身不应被限定为 standards、protocols、maps、databases 或 interoperability organization。它可以长期承载研究、工具、公共知识工作、基础设施以及未来尚未出现的项目形式。

## 3. Mission / 使命

> **Enable knowledge to move from the commons, through individual perspective, into creation — and back to the commons.**
>
> **让知识从公共知识域流向个人，经由个人视角转化为理解与创造，并让新的成果重新回到公共知识域。**

使命描述组织为何存在，以及它长期持续推动什么变化。

组织的工作不是替个人形成唯一视角，也不只是积累更多信息；它要改善知识进入、理解、连接、转化、创造与回流所需要的条件，使这一循环更开放、更可持续，也更能被人和工具共同使用。

## 4. Change Model / 变化模型

**Commons → Perspective → Creation → Commons ↺**

- **Commons / 公共知识域**：可共同获取、引用、组合与延续的知识、标准、工具和其他公共资源。
- **Perspective / 个人视角**：个体基于共同知识形成的理解、关联、判断、选择与上下文。
- **Creation / 创造**：由个人视角进一步产生的新知识、作品、工具、研究、系统与行动。
- **Return / 回流**：新的成果以可共享、可复用的方式重新进入 commons，并成为下一轮理解与创造的基础。

这个循环是组织理解“知识如何产生长期公共价值”的核心模型。它不是线性漏斗，而是持续反馈和扩展的循环。

## 5. Enabling Principles / 实现原则

这些原则服务于使命与变化模型，但它们本身不是组织最终目的：

- **Openness / 开放**：尽可能降低知识与能力被获取、理解、使用和再创造的门槛。
- **Interoperability / 互操作**：减少知识、工具、系统与 Agent 之间不必要的连接障碍。
- **Composability / 可组合**：让知识与能力能够被重新连接、组合并形成新的用途。
- **Individual Agency / 个人主体性**：公共基础和智能工具应扩展个人形成视角与创造的能力，而不是替代个人视角。
- **Reciprocity / 回流与互惠**：创造不仅从 commons 获取，也应保留重新贡献、复用和扩展 commons 的路径。

## 6. Relationship to InteropAtlas / 与 InteropAtlas 的关系

**InteropAtlas 是这套组织级哲学与使命之下的一个具体项目，而不是组织本身的边界。**

InteropAtlas 主要处理其中的 interoperability 层：理解和描绘标准、协议、接口、兼容关系与开放缺口，降低知识、工具、系统和 Agent 之间的连接成本。

因此：

- 组织关注的是更完整的 **Commons → Perspective → Creation → Commons ↺** 循环；
- InteropAtlas 重点解决让这个循环得以发生的一类基础条件——**interoperability**；
- 未来其他项目可以分别作用于 commons、perspective、creation 或它们之间的连接，而不需要被 InteropAtlas 当前的产品形态所限制。

## 7. Identity Hierarchy / 身份层级

从稳定到具体，组织身份按以下层级理解：

**Philosophy / 世界观**  
→ 我们相信什么

**Vision / 愿景**  
→ 如果长期成功，我们希望世界呈现什么状态

**Mission / 使命**  
→ 我们为何存在、持续推动什么变化

**Change Model / 变化模型**  
→ 我们认为这种变化如何形成循环

**Principles / 原则**  
→ 我们在实现过程中坚持什么

**Projects / 项目**  
→ 在特定问题空间中的具体实践，例如 InteropAtlas

---

这套基础定义属于组织级 canonical identity。各项目可以继承并具体化它，但不应反过来用某个单一项目当前的边界重新定义整个组织。
